# 7. Vulnerabilities

Three vulnerabilities were intentionally introduced into the application.

---

## 7.1 SQL Injection

### Description

SQL Injection occurs when untrusted user input is directly incorporated into an SQL query without proper parameterization.

For example, an insecure implementation may construct a query by concatenating user input:

```java
String query = "SELECT * FROM books WHERE title = '" + userInput + "'";
```

The value supplied by the user becomes part of the SQL statement.

### Vulnerable Component

The vulnerability is introduced in the book search/database operation.

### Security Impact

An attacker may be able to:

* Retrieve unauthorized database information.
* Modify database records.
* Delete records.
* Bypass intended database restrictions.

### Detection

The SAST tool can identify the flow of untrusted input into database queries and report the potentially unsafe SQL construction.

### Recommended Mitigation

Use parameterized queries or prepared statements.

Example:

```java
PreparedStatement stmt =
    connection.prepareStatement(
        "SELECT * FROM books WHERE title = ?");
stmt.setString(1, userInput);
```

Parameterized queries prevent user input from being interpreted as part of the SQL command.

---

## 7.2 Cross-Site Scripting (XSS)

### Description

Cross-Site Scripting occurs when untrusted user input is displayed without appropriate validation or output encoding.

Although the application is primarily console-based, the vulnerability can be demonstrated if user-controlled library information is displayed through an HTML/web interface or HTML-formatted output.

Example malicious input:

```text
<script>alert('XSS')</script>
```

If this input is inserted into an HTML page without proper encoding, the browser may interpret it as executable JavaScript.

### Vulnerable Component

The vulnerability can occur when user-controlled member or book information is displayed without appropriate output encoding.

### Security Impact

XSS may allow an attacker to:

* Execute JavaScript in another user's browser.
* Modify displayed content.
* Steal sensitive browser information.
* Perform actions on behalf of the victim.

### Detection

The SAST tool can detect potentially unsafe flows where user-controlled input reaches an HTML output location without proper sanitization or encoding.

### Recommended Mitigation

* Validate user input.
* Encode output before displaying it.
* Use safe templating mechanisms.
* Do not directly insert untrusted input into HTML.

---

## 7.3 Improper Input Validation

### Description

Improper Input Validation occurs when the application accepts user input without properly checking its type, format, range, or expected values.

Examples include:

* Negative book IDs
* Invalid member IDs
* Invalid dates
* Empty names
* Unexpected characters
* Invalid numeric values

For example, an application may accept:

```text
Book ID: -100
```

when a valid book ID should only contain a positive integer.

### Security Impact

Improper input validation can cause:

* Application errors.
* Incorrect database records.
* Unexpected application behavior.
* Security vulnerabilities.
* Potential denial-of-service conditions in poorly designed applications.

### Detection

The SAST tool can identify user input that reaches sensitive operations without sufficient validation.

### Recommended Mitigation

Input should be validated before processing.

For example:

```java
if (bookId <= 0) {
    System.out.println("Invalid Book ID");
    return;
}
```

Validation should include:

* Type validation
* Range validation
* Length validation
* Format validation
* Null/empty checks

# 12. Remediation

The vulnerabilities introduced in the intentionally vulnerable version can be addressed using secure coding practices.

### SQL Injection

Use prepared statements instead of constructing SQL queries through string concatenation.

### XSS

Validate input and encode output before displaying user-controlled information.

### Improper Input Validation

Validate every input according to its expected type, range, length, and format.
